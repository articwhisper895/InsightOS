# Security Policy

## Reporting a vulnerability

Please do not publish suspected vulnerabilities in public issues, discussions, or pull requests.

Use GitHub's **Private vulnerability reporting** feature for this repository when it is enabled. If it is unavailable, contact the repository owner privately through a verified channel listed on the owner's GitHub profile.

A useful report includes:
- the affected component, version, or commit;
- the potential impact;
- clear reproduction steps;
- relevant logs or proof of concept, with secrets and personal data removed.

## Response expectations

Reports will be reviewed as maintainer capacity allows. Additional details may be requested, and remediation and disclosure will be coordinated with the reporter where practical. Do not assume an issue is fixed until a release or written confirmation says so.

## Scope

This policy applies to code and services explicitly maintained as part of InsightOS. Vulnerabilities in third-party services should be reported through the relevant provider's security process.
