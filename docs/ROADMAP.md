# Roadmap

This roadmap is organised around outcomes. Items should move to **In progress** only when implementation has started and to **Completed** only after verification.

## Foundation

- [ ] Connect the actual application source code to this repository.
- [ ] Confirm product scope, primary user workflows, and success criteria.
- [ ] Record the application stack and reproducible local setup.
- [ ] Establish code quality, test, and accessibility baselines.
- [ ] Define core design tokens and shared component conventions.

## Experience

- [ ] Implement and document the responsive application shell and navigation.
- [ ] Define and test supported theme behaviour.
- [ ] Implement restrained ambient background and geometric texture treatments.
- [ ] Establish accessible interaction, loading, empty, error, and feedback states.
- [ ] Verify time-sensitive behaviour across timezones and date boundaries.

## Reliability and release

- [ ] Add automated tests for critical workflows.
- [ ] Add dependency and secret-management practices.
- [ ] Document deployment, monitoring, backup, and rollback procedures.
- [ ] Prepare release notes and a verified project profile.

## Roadmap policy

Keep this list honest. Link completed items to the relevant pull request, issue, test evidence, or release. Move deferred work to an explicitly labelled backlog rather than leaving stale promises in the active roadmap.
